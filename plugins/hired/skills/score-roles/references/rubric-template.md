# Rubric template

The structure the setup interview fills in. Written to the **Pipeline Config** page in
Notion under `## Rubric`, where the user can edit it any time. Editing it there changes
scoring on the next run.

Everything below is a shape to fill, not content to copy. Blank sections are better than
invented ones: the scorer treats an empty dimension as neutral, but a wrong dimension
distorts every score.

---

## Hard filters

Rules that cap a score no matter what else is true. Each one states the exact boundary
and the cap it applies.

- [Filter]: [exact boundary]. Caps at [Very Low / Low].

## Standout logic

Optional. The combination of things that makes this person an unusual candidate rather
than a merely qualified one.

Dimensions:

1. [Dimension]: [what it covers, and why it is credible for this person]
2. [Dimension]: ...
3. [Dimension]: ...

How the score responds:

- Hits all: [floor, e.g. Very High]
- Hits two: [floor, e.g. High]
- Hits one: score on the dimensions below, no boost
- Hits none: [cap, or "no cap" if the user chose a nudge instead]

Standout logic sits on top of the dimensions, not instead of them. Hard filters still
apply: a perfect standout role that fails a location filter is still capped.

spectrum.

- Weak: [concrete signals]
- Type: [filter / spectrum]

### 2. [Dimension name]
...

Most important when breaking a tie: [dimension], then [dimension].

## Tier definitions

- **Very High**: [meaning]. Action: [tailor / apply / watch / ignore]. Expected: about [N]
  in 20.

- **Medium**: [meaning]. Action: [...].
- **Low**: [meaning]. Action: [...].
- **Very Low**: [meaning]. Action: [...].

## Calibration anchors

Two real postings scored during setup. Keep these. They are how you tell later whether
scoring has drifted.

- [Company, title]: **[tier]**. Why: [reasoning]
- [Company, title]: **[tier]**. Why: [reasoning]
